## 1. JWT 토큰 정책

| 항목 | 값 |
|---|---|
| 라이브러리 | `djangorestframework-simplejwt` |
| 알고리즘 | HS256 (대칭키, `SECRET_KEY` 사용) |
| **Access Token TTL** | **30분** |
| **Refresh Token TTL** | **14일** |
| **Refresh Rotation** | **사용** (갱신 시 새 refresh 발급 + 이전 무효화) |
| **Refresh Blacklist** | **사용** (로그아웃·비밀번호 변경 시 무효화) |

## 2. 토큰 저장 정책 (보안 강화 v2)

**금융 서비스 컨셉에 맞춰 토큰 저장을 분리.**

| 토큰 | 저장 위치 | 보안 효과 |
|---|---|---|
| **Access** | LocalStorage | XSS 노출 가능하나 TTL 30분으로 제한 |
| **Refresh** | **HttpOnly Cookie** | JS가 못 읽음 → XSS 완전 차단 |

### 2.1 Refresh Cookie 속성

```
Set-Cookie: refresh_token=<jwt>;
            HttpOnly;
            Secure;
            SameSite=Strict;
            Path=/api/v1/auth/token;
            Max-Age=1209600
```

- **HttpOnly**: JS의 `document.cookie`로 못 읽음 → XSS 방어
- **Secure**: HTTPS에서만 전송 → 중간자 공격 방어
- **SameSite=Strict**: 다른 사이트에서 우리 API로의 요청에 Cookie 자동 첨부 안 됨 → CSRF 방어
- **Path 제한**: refresh 호출 시에만 전송 → 노출 범위 최소화
- **Max-Age**: 14일

### 2.2 클라이언트 흐름

```javascript
// 로그인
const { access } = await api.post('/auth/login',
  { email, password },
  { withCredentials: true }
);
localStorage.setItem('access', access);
// refresh는 브라우저가 Cookie로 자동 저장 (JS는 모름)

// 일반 API 호출
api.get('/portfolio', {
  headers: { Authorization: `Bearer ${localStorage.getItem('access')}` }
});

// access 만료 → 401 → 자동 재발급
await api.post('/auth/token/refresh', {}, { withCredentials: true });
// 본문에 refresh 안 넣어도 됨. Cookie로 자동 전송
```

## 3. Refresh Rotation 동작

```
[t=0]     로그인 → access(A1, 30분) + refresh(R1, 14일, Cookie)
[t=30분]  access 만료 → /auth/token/refresh 호출 (Cookie 자동 첨부)
                       서버: A2 + R2 발급, R1 블랙리스트
[t=60분]  A2 만료 → R2 갱신 → A3, R3
...
[t=14일]  R 만료 → 401 → 로그인 페이지로
```

매번 refresh가 회전하므로 R1이 탈취돼도 R2 발급 시점에 즉시 무효화됩니다.

## 4. 권한 매트릭스 (RBAC)

### 4.1 역할

```
일반 사용자 (User)  ← 대부분
관리자 (Admin)     ← Django admin 패널만, 서비스 화면엔 어드민 없음
```

### 4.2 DRF 권한 클래스

| 클래스 | 의미 | 적용 예시 (자원) |
|---|---|---|
| `AllowAny` | 누구나 | Stock, News, 공개 Post 조회 |
| `IsAuthenticated` | 로그인만 됐으면 OK | Recommend, Post 작성, Watchlist 추가 |
| `IsOwner` (커스텀) | 본인 데이터만 | **Diary, Account, Order, Holding, 자기 Post 수정** |
| `IsAdminUser` | Django admin만 | (사용 안 함) |

### 4.3 IsOwner 커스텀 권한

```python
# accounts/permissions.py
class IsOwner(permissions.BasePermission):
    def has_object_permission(self, request, view, obj):
        return obj.user == request.user
```

ViewSet에 적용:

```python
class DiaryViewSet(viewsets.ModelViewSet):
    permission_classes = [IsAuthenticated, IsOwner]

    def get_queryset(self):
        return Diary.objects.filter(user=self.request.user)  # ← 본인 것만 쿼리

class OrderViewSet(viewsets.ModelViewSet):
    permission_classes = [IsAuthenticated, IsOwner]

    def get_queryset(self):
        return Order.objects.filter(user=self.request.user)
```

| 이벤트 | 동작 |

## 6. 추가 보안 강화 (금융 서비스 특화)

### 6.1 Rate Limiting (필수)

`django-ratelimit` 으로 무차별 대입 방어.

```python
# pip install django-ratelimit
from django_ratelimit.decorators import ratelimit

class LoginView(APIView):
    @method_decorator(ratelimit(key="ip", rate="5/m", method="POST", block=True))
    def post(self, request):
        ...
```

**적용 대상**:
- `/auth/login` — 분당 5회
- `/auth/signup` — 분당 3회
- `/auth/password/reset` — 분당 3회
- `/orders` — 사용자당 분당 30회 (자동화 매매 차단)
- `/orders/preview` — 사용자당 분당 60회

초과 시 `429 Too Many Requests` 응답.

## 8. Django 모델 매핑 (ERD 1:1 매칭)

이 정책에서 참조하는 핵심 모델과 ERD 테이블의 매핑.

| Django 모델 (앱.Model) | ERD 테이블 | 관계 / 비고 |
|---|---|---|
| `accounts.User` (AbstractUser 확장) | `USER` | username, email, nickname, birth_year |
| `accounts.InvestmentProfile` | `USER_INVESTMENT_PROFILE` | User와 **OneToOne** (1:1) |
| `portfolio.Account` | `ACCOUNT` | User와 **OneToOne** (1:1), balance |
| `portfolio.Order` | `ORDER` | User와 1:N. `idempotency_key` unique |
| `portfolio.Holding` | `HOLDING` | (user, stock) **unique_together** |
| `accounts.RefreshTokenBlacklist` | (simplejwt 내장) | `OutstandingToken` + `BlacklistedToken` |

### 8.1 회원가입 시 ACCOUNT 자동 생성

회원가입 트랜잭션에 `User` 생성 + `Account` 생성을 묶음:

```python
@transaction.atomic
def signup(email, password, nickname, birth_year, ...):
    user = User.objects.create_user(
        email=email,
        password=password,
        nickname=nickname,
        birth_year=birth_year,
    )
    Account.objects.create(
        user=user,
        balance=Decimal("100000000"),       # 초기 1억
        initial_balance=Decimal("100000000"),
    )
    return user
```

`Account`는 별도 view에서 생성하지 않고 회원가입 시 자동. 별도 충전 기능은 시연용으로만 (관리자 admin).

### 8.2 비밀번호 변경 시 토큰 무효화

```python
def change_password(user, new_password):
    user.set_password(new_password)
    user.save()
    # 사용자의 모든 refresh 토큰 블랙리스트
    OutstandingToken.objects.filter(user=user).delete()
```
