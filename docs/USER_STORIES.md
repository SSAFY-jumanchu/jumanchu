# 주만추 사용자 스토리

> 기획서 docx의 기능 요구사항 11개(F01~F11)를 사용자 스토리 형식으로 정리한 문서.
> Phase 1 SCRUM-19(문제 정의 / 사용자 스토리)의 산출물.
>
> 각 스토리는 다음을 포함한다:
> - **사용자 가치** ("나는 ~로서 ~하고 싶다")
> - **인수 조건** (Acceptance Criteria — 동작 검증 기준)
> - **우선순위** (P0 필수 / P1 선택 / P2 여유)
> - **관련 화면 / 데이터 / API 초안**

---

## 0. 우선순위 요약

| 우선순위 | 의미 | 스토리 |
|---|---|---|
| **P0 (필수)** | MVP 시연/발표에 반드시 동작 | US-01 ~ US-06, US-08, US-11 (8개) |
| **P1 (선택)** | 시간이 남으면 포함 | US-07, US-09 (2개) |
| **P2 (여유)** | 최후 우선순위 | US-10 (1개) |

스토리 키 ↔ 기능 매핑: `US-NN ↔ F0N`

---

## US-01. 종목 검색  (F01)

**우선순위**: P0 / **컴포넌트**: backend + frontend

> 나는 투자자로서, 종목 이름이나 코드를 알 때 그것으로 빠르게 종목 상세 페이지에 도달하고 싶다.

**인수 조건**
- [ ] 검색창에 키워드를 입력하면 키워드를 포함하는 종목 리스트가 보인다
- [ ] 한국(KOSPI/KOSDAQ)과 미국(S&P500/나스닥100) 종목을 모두 검색할 수 있다
- [ ] 검색 결과 항목을 클릭하면 종목 상세 페이지로 이동한다
- [ ] 결과가 없으면 "검색 결과가 없습니다" 안내 메시지가 표시된다
- [ ] 검색 응답 시간은 1초 이내 (NF03)

**관련**
- 화면: 주식 목록 페이지
- 데이터: 주식 종목 마스터 데이터 (pykrx / yfinance)
- API 초안: `GET /api/v1/stocks/search?q={keyword}&market={KR|US}`

---

## US-02. 회원가입  (F02)

**우선순위**: P0 / **컴포넌트**: backend + frontend

> 나는 신규 사용자로서, 이메일과 비밀번호로 가입하여 주만추 서비스를 시작하고 싶다.

**인수 조건**
- [ ] 이메일 형식이 올바르지 않으면 에러 메시지가 보인다
- [ ] 비밀번호는 8자 이상 + 영문/숫자 조합이어야 한다
- [ ] 이미 가입된 이메일이면 안내 메시지가 표시된다
- [ ] 가입 성공 시 온보딩 화면으로 이동한다
- [ ] 비밀번호는 DB에 해시 저장된다 (NF05)

**관련**
- 화면: 회원가입 페이지, 온보딩 페이지
- 데이터: User 모델 (AbstractUser 상속, 커스텀 필드)
- API 초안: `POST /api/v1/auth/signup`

---

## US-03. 로그인  (F03)

**우선순위**: P0 / **컴포넌트**: backend + frontend

> 나는 등록된 사용자로서, 내 계정으로 로그인하여 개인 데이터에 접근하고 싶다.

**인수 조건**
- [ ] 이메일/비밀번호가 일치하면 로그인되고 홈 페이지로 이동한다
- [ ] 비밀번호가 틀리면 "이메일 또는 비밀번호가 일치하지 않습니다" 메시지가 보인다 (어느 필드인지 노출 X)
- [ ] 로그인 상태는 새로고침 후에도 유지된다 (세션 또는 토큰)
- [ ] 로그아웃 시 보호된 페이지에서 자동으로 로그인 페이지로 리다이렉트된다
- [ ] HTTPS로 통신한다 (NF05)

**관련**
- 화면: 로그인 페이지
- 데이터: User 모델, 세션/토큰 저장소
- API 초안: `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`

## US-04. 투자 패턴 기반 종목 추천 (스와이프)  (F04)

**우선순위**: P0 / **컴포넌트**: backend + algo + frontend

> 나는 사용자로서, 내 투자 패턴(과거 매수/매도/관심 이력)에 맞는 종목을 스와이프 방식으로 둘러보며 관심 종목을 빠르게 등록하고 싶다.

**인수 조건**
- [ ] 추천 페이지 진입 시 스와이프 카드 스택이 보인다 (Tinder식)
- [ ] 오른쪽 스와이프 = 관심 등록, 왼쪽 스와이프 = 패스
- [ ] 카드에는 종목명, 현재가, 등락률, 한줄 설명(OpenAI 생성)이 표시된다
- [ ] 추천 후보는 룰베이스(투자 성향 + 종목 위험성향 매칭)로 산출된다
- [ ] 콜드스타트(데이터 없음) 시: 랜덤 또는 트렌딩 종목으로 폴백
- [ ] 한 세션에 최소 10개 카드가 제공된다

**관련**
- 화면: 추천 종목 화면 (스와이프 UI), 홈 페이지 (추천 섹션)
- 데이터: 사용자 행동 데이터, 종목 위험성향 분류, AI 분석 결과
- Algo 함수 초안: `recommend_by_user_pattern(user_id: int, limit: int) -> list[StockRecommendation]`
- API 초안: `GET /api/v1/recommend/pattern?limit=10`

## US-05. 트렌딩 뉴스 기반 종목 추천 (스와이프)  (F05)

**우선순위**: P0 / **컴포넌트**: backend + algo + frontend

> 나는 사용자로서, 요즘 화제가 되는 뉴스와 관련된 종목을 스와이프로 둘러보며 새 관심 종목을 발견하고 싶다.

**인수 조건**
- [ ] 추천 페이지에서 "뉴스 기반 추천" 탭을 선택하면 뉴스 관련 종목 카드가 보인다
- [ ] 카드에는 종목명, 현재가, 등락률, 관련 뉴스 제목/링크가 표시된다
- [ ] 뉴스 → 관련주 매핑은 Algo가 담당 (키워드 매칭 + 종목 동의어 사전)
- [ ] 한국 뉴스(NewsData.io / Gnews) + 미국 뉴스 모두 활용
- [ ] 추천 결과는 1시간 이상 캐싱

**관련**
- 화면: 추천 종목 화면 (스와이프 UI, 뉴스 탭)
- 데이터: 미국/한국 뉴스, 주식 종목 마스터 데이터
- Algo 함수 초안: `recommend_by_trending_news(limit: int) -> list[StockRecommendation]`
- API 초안: `GET /api/v1/recommend/news?limit=10`

## US-06. 종목 상세 조회  (F06)

**우선순위**: P0 / **컴포넌트**: backend + frontend

> 나는 사용자로서, 관심 있는 종목의 시세·차트·기본 정보를 한 페이지에서 확인하고 싶다.

**인수 조건**
- [ ] 종목 상세 페이지 진입 시 종목명, 현재가, 등락률, 거래량이 보인다
- [ ] 일/주/월봉 차트를 전환하며 볼 수 있다
- [ ] 미국 종목은 원화 환산 가격도 함께 표시된다
- [ ] 시세 데이터는 API 호출 결과를 DB 캐시 (장중 1분, 장외 5분)
- [ ] 관련 뉴스 탭 / 재무제표 탭 / 일기 작성 버튼이 함께 노출된다

**관련**
- 화면: 종목 상세 페이지
- 데이터: 실시간 주식 시세 (KIS / yfinance), 환율 (ECOS), 뉴스
- API 초안: `GET /api/v1/stocks/{ticker}`, `GET /api/v1/stocks/{ticker}/chart?period={day|week|month}`

## US-07. 커뮤니티 — 포트폴리오·종목 공유  (F07)

**우선순위**: P1 / **컴포넌트**: backend + frontend

> 나는 사용자로서, 내 포트폴리오나 종목에 대한 의견을 다른 사용자와 공유하고 그들의 의견도 참고하고 싶다.

**인수 조건**
- [ ] 커뮤니티 페이지에서 최신 게시글 리스트가 보인다
- [ ] 게시글에는 제목·본문·작성자·작성일·좋아요 수·댓글 수가 표시된다
- [ ] 로그인한 사용자만 게시글 작성/댓글 작성 가능
- [ ] 게시글 본문에 종목 태그를 달면 종목 상세 페이지로 링크된다
- [ ] PRG 패턴 적용 (작성 후 새로고침해도 중복 작성 안 됨)

**관련**
- 화면: 커뮤니티 페이지, 게시글 상세 페이지
- 데이터: Post, Comment 모델
- API 초안: `GET/POST /api/v1/community/posts`, `GET/POST /api/v1/community/posts/{id}/comments`

## US-08. 종목 재무제표 조회  (F08)

**우선순위**: P0 / **컴포넌트**: backend + frontend

> 나는 사용자로서, 종목의 분기/연간 재무제표를 한눈에 보고 펀더멘털을 판단하고 싶다.

**인수 조건**
- [ ] 종목 상세 페이지의 "재무제표" 탭에서 매출/영업이익/순이익/부채비율을 분기·연간으로 볼 수 있다
- [ ] 한국 종목 = DART OpenAPI, 미국 종목 = yfinance 데이터로 자동 분기
- [ ] 최근 4분기 + 최근 3개 연도 데이터가 차트로 표시된다
- [ ] 데이터 없음 (신규 상장 등) 시 안내 메시지가 보인다
- [ ] 데이터는 일 1회 배치 갱신 (요청 시 캐시 우선)

**관련**
- 화면: 종목 상세 페이지 (재무제표 탭)
- 데이터: 한국 기업 재무제표 (DART), 미국 기업 재무제표 (yfinance)
- API 초안: `GET /api/v1/stocks/{ticker}/financials?period={Q|Y}`

## US-09. 매수/매도/관심 일기  (F09)

**우선순위**: P1 / **컴포넌트**: backend + frontend (+ algo 입력)

> 나는 사용자로서, 종목 매수/매도/관심 등록 시점에 그 이유와 감정을 기록하고 나중에 회고하고 싶다.

**인수 조건**
- [ ] 종목 상세 페이지 또는 일기장 페이지에서 일기를 작성할 수 있다
- [ ] 일기 항목: 종목, 행위(매수/매도/관심), 가격, 수량(매매시), 이유 텍스트, 작성일
- [ ] 일기 리스트는 종목별 / 날짜별 필터링 가능
- [ ] 일기 텍스트는 OpenAI로 분석되어 투자 MBTI 입력으로 사용됨 (US-10)
- [ ] 일기는 본인만 조회/수정/삭제 가능

**관련**
- 화면: 일기장 페이지, 종목 상세 페이지 (일기 작성 버튼)
- 데이터: Diary 모델
- API 초안: `GET/POST /api/v1/diary`, `PATCH/DELETE /api/v1/diary/{id}`

## US-10. 투자 MBTI / 성향 트래킹  (F10)

**우선순위**: P2 / **컴포넌트**: backend + algo + frontend

> 나는 사용자로서, 내 매매 이력과 일기를 바탕으로 "당신은 어떤 투자자다"라는 성향 리포트를 받아보고 싶다.

**인수 조건**
- [ ] 프로필 페이지의 "투자 MBTI" 섹션에서 본인의 투자 성향 유형이 보인다 ("ENFP형 투자자" 등)
- [ ] 분류 근거(매매 빈도, 위험 선호, 일기 키워드 등) 요약이 함께 표시된다
- [ ] 최소 일기 5개 이상 작성 후에만 리포트가 생성된다 (이전: "더 많은 기록이 필요해요" 안내)
- [ ] 리포트는 월 1회 자동 갱신 + 수동 갱신 버튼 제공

**관련**
- 화면: 프로필 페이지, 투자 MBTI 페이지
- 데이터: 사용자 행동 데이터, 일기 데이터, AI 분석 결과
- Algo 함수 초안: `classify_investor_mbti(user_id: int) -> InvestorProfile`
- API 초안: `GET /api/v1/profile/mbti`, `POST /api/v1/profile/mbti/refresh`

## US-11. 홈 (시장 요약 + 내 포트폴리오 현황)  (F11)

**우선순위**: P0 / **컴포넌트**: backend + frontend

> 나는 사용자로서, 홈에 진입했을 때 오늘의 시장 상황과 내 자산 현황을 한눈에 파악하고 싶다.

**인수 조건**
- [ ] 홈 상단: 코스피·코스닥·S&P500·나스닥 지수와 환율(USD/KRW)
- [ ] 홈 중단: 내 포트폴리오 평가 손익, 자산 배분 차트, 보유 종목 리스트
- [ ] 홈 하단: 커뮤니티 최신 글 미리보기, 네비게이션 바
- [ ] 비로그인 상태에서는 시장 요약만 보이고, 포트폴리오 영역은 "로그인 안내"로 대체된다
- [ ] 메인 페이지의 모든 위젯이 3초 이내 렌더링 (NF02)

**관련**
- 화면: 홈 페이지
- 데이터: 시세, 환율, 사용자 보유 종목
- API 초안: `GET /api/v1/market/summary`, `GET /api/v1/portfolio/me`
