# 서비스 흐름도 정리

> 본 문서는 팀 프로젝트(Django 기반 금융 서비스)의 사용자 흐름과 메인 페이지 구성을 정리한 자료입니다. 강사님 피드백을 받기 위한 초안입니다.

---

## 1. 전체 사용자 흐름

```
[로그인 / 회원가입]
        │
        ▼
[온보딩 — 투자성향 파악]
        │
        ▼
[마이페이지 — 추천]
        │
        ▼
     [index (메인)]
        │
        ▼
    [자동 APIs 탑재]   ※ 외부 API 자동 연동
```

---

## 2. 단계별 상세

### ① 로그인 / 회원가입
- 사용자 기본 정보 입력
- 인증 방식: Django 기본 인증 + 커스텀 유저 모델(`AbstractUser` 상속)
- 회원가입 / 로그인 / 로그아웃 / 프로필 수정 / 비밀번호 변경 지원

### ② 온보딩 — 투자성향 파악
- 설문 기반 사용자 분류
- 분류 예시
  - 고위험형
  - 안정형
  - 단정형 *(명칭 재확인 필요)*
  - 기타
- 결과는 사용자 모델 필드 또는 별도 Profile 모델에 저장

### ③ 마이페이지 — 추천
- 투자성향 결과 기반 **예·적금 상품 추천**
- 사용자가 추천 받기 / 받지 않기 선택 가능
- 추천 비활성화 시: 기본 인덱스(시장 정보 중심)로 이동

### ④ index (메인 페이지)
| No | 메뉴 | 설명 |
| --- | --- | --- |
| 1 | My Page | 계좌 관리, 개인 자산 요약 |
| 2 | 예·적금 | 상품 조회 / 작성 / 비교 |
| 3 | 자산 조회 | 보유 종목, 수익률 등 |
| 4 | 커뮤니티 | 포트폴리오 공유 등 |
| 5 | 뉴스 | 시장 / 종목 관련 뉴스 |
| 6 | 기타 | (확정 필요) |

### ⑤ 메인 페이지 구성 요소 *(판독 추정)*
1. 정보 영역
2. 시장 요약 · 뉴스 · 종목 자산
3. 추천 종목 (테마별)
4. 포트폴리오 추천
5. 투자전략 (지표 분석 / 신경망 기반)

## 3. 강사님 피드백을 받기 전 자체 점검 포인트

### 3-1. 페이지 구조의 정합성
"마이페이지(추천)"와 index 하위 "My Page(계좌 관리)"가 같은 페이지인지 다른 페이지인지 모호함.
→ **추천 페이지**와 **마이페이지(계좌)**를 분리하거나, 명칭을 통일해야 함.

### 3-2. 추천 로직의 근거
- 투자성향 → 상품 매칭 로직이 흐름도에 명시되지 않음.
- 4주 스코프 기준 현실적 방안:
  - **룰베이스 매칭** (성향별 카테고리 가중치)
  - 협업필터링·ML 기반은 후순위

### 3-3. 데이터 소스
- 예·적금 → 금융감독원 금융상품통합비교공시 OpenAPI
- 주식 시세 → 한국투자증권 KIS API / pykrx
- 뉴스 → 네이버 뉴스 API / RSS
- 캐싱 전략(DB 캐시 or Redis) 사전 결정 필요

### 3-4. Django 학습 목표와의 매핑
강사님은 Django의 어떤 기능을 활용했는지 확인하실 가능성이 큼. 흐름도 옆에 학습 요소를 매핑할 것:
- 커스텀 유저 모델 → 회원가입
- M2M (User ↔ Stock) → 자산 조회
- PRG 패턴 → 게시판 작성
- messages framework → 알림 처리
- JSON 로딩 관리 커맨드 → 초기 상품 데이터 적재

### 3-5. 비로그인 사용자 흐름
- 어디까지 비로그인으로 접근 가능한지 정의 필요
- 예시 정책
  - 공개: 뉴스, 시장 요약, 예·적금 일반 조회
  - 로그인 필요: 추천, 자산 조회, 커뮤니티 작성

### 3-6. 금융 도메인 특수성
- "추천"이라는 표현은 투자자문업 규제 이슈가 있음.
- UI 카피는 "정보 제공" 톤으로 (예: "당신과 비슷한 성향의 사용자가 본 상품")
- 면책 문구, 개인정보 처리방침 페이지 자리 확보 필요

### 3-7. MVP 스코프 우선순위
6개 메뉴 전부를 4주 안에 완성하는 것은 비현실적. 우선순위 명시:

| 우선순위 | 기능 |
| --- | --- |
| 필수 (P0) | 회원가입/로그인, 온보딩, 예·적금 추천, 메인 |
| 선택 (P1) | 자산 조회, 뉴스 |
| 여유 (P2) | 커뮤니티, 포트폴리오 추천 |

### 3-8. 예외 / 실패 흐름
- 로그인 실패
- 외부 API 응답 실패 (타임아웃, rate limit)
- 종목 데이터 없음
- 추천 결과 없음 (콜드스타트)

흐름도에 정상 경로만 있으므로 분기를 1~2개라도 추가하면 완성도 상승.

1. 추천 로직을 룰베이스로 가는 것이 평가상 충분한가요? ML 시도가 필요한가요?
2. 외부 API 의존도가 높은데, 데이터 사전 적재 vs 실시간 호출 중 어느 쪽을 권장하시나요?
3. 커뮤니티 기능(P2)은 빼는 것이 좋을까요, 최소 형태로 남기는 것이 좋을까요?
4. 금융 자문업 규제 관련 면책 처리는 어느 수준까지 필요한가요?
