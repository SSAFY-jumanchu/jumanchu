# 장투 점수 산정 로직

> 장투 케어(장투 페이지)의 **장기보유 점수** 산정 기준.
> 정율 `ALGORITHM_DB_OPTIMIZATION_SPEC.jy.md` §3-6② 기반 + 화면 시각화 지표에 맞게 확장.
> 결정일: 2026-06-10

---

## 1. 종합 점수 — `long_term_score.total`

```
total = 재무 × 0.30  +  성장 × 0.40  +  궁합 × 0.30
```

| 등급 | 구간 |
|---|---|
| A | ≥ 90 |
| B+ | ≥ 80 |
| B | ≥ 70 |
| C | ≥ 60 |
| D | < 60 |

> 가중치 결정: **재무 30 / 성장 40 / 궁합 30** (성장 비중 최대 — 장기 투자 관점).

---

## 2. 축별 산식

### ① 재무 점수 (30%) — `financial_summary` + `stock_indicator`
4개 지표를 각각 0~100으로 환산 후 **평균**.

| 지표 | 환산식 | 방향 |
|---|---|---|
| 부채비율 | `100 − min(부채비율, 200) / 2` | 낮을수록 ↑ (0%→100, 200%→0) |
| ROE | `min(ROE × 5, 100)` | 높을수록 ↑ (20%→100) |
| 영업이익률 | `min(영업이익률 × 4, 100)` | 높을수록 ↑ (25%→100) |
| 유동비율 | `min(유동비율 / 2, 100)` | 높을수록 ↑ (200%→100) |

```
재무 = (부채점수 + ROE점수 + 영업이익률점수 + 유동비율점수) / 4
```
> 정율 base(`100 − 부채/4 + 유동/10`)를 4지표로 확장.

### ② 성장 점수 (40%) — `financial_summary`
| 지표 | 환산식 |
|---|---|
| 매출성장률 YoY | `clamp(50 + revenue_yoy, 0, 100)` |
| 순이익성장률 YoY | `clamp(50 + net_profit_yoy, 0, 100)` |
| EPS 증가율 | `clamp(50 + eps_yoy, 0, 100)` |

```
성장 = (매출점수 + 순이익점수 + EPS점수) / 3
```
> 정율 base = `50 + revenue_yoy + net_profit_yoy`(합산). 여기선 **지표별 평균**으로 과대 캡 방지.
> ※ `eps_yoy` 컬럼이 없으면 `net_profit_yoy`를 프록시로 사용(정율 §3-6 가정).

### ③ 궁합 점수 (30%) — `investment_profile` + `stock_dna`
**= 온보딩 궁합 점수(`match_score`) 그대로 재사용.** (정율 5요소 가중합)

```
match = risk×0.35 + sector×0.20 + term×0.15 + exp×0.15 + style×0.15
각 요소 = (1 − |유저값 − 종목DNA값| / 범위) × 100
값 없으면 50 (중립)
```
> 보유 종목은 `recommendation_cache.match_score`에 있으면 재사용, 없으면 라이브 계산.
> 정확한 5요소 가중치는 정율 궁합 산식을 따른다(risk 비중 최대).

## 3. 변별력 — 절대식 vs 분위수

| 방식 | 장 | 단 |
|---|---|---|
| **절대식**(위 표) | 단순·빠름, 배치 불필요 | 우량주가 만점 근처로 몰려 변별력 낮음 |
| **분위수(percentile)** | 변별력 좋음 | 일배치로 전체 종목 분포 계산 필요 |

→ **데모는 절대식으로 시작**, 변별력 필요해지면 분위수로 전환. (정율도 stock_dna에 "min-max or 분위수" 명시)
→ 상수(`÷2`, `×5` 등)는 **튜닝값**. 로직(지표·방향·정규화·가중치)이 본질.

---

## 4. LLM 보고서 = 캐싱 (DB 아님) ⚠️

장투 페이지의 **4개 서술 보고서**(종합·재무·성장·궁합)는 OpenAI 생성.

- **저장: Redis 캐시** (lazy 생성 + TTL). **DB 테이블 X.**
- 키: `lt_report:{code}:{score_date}` → **점수 일배치와 동기화** (점수 바뀌면 보고서 재생성).
- 입력: 계산된 3축 점수 + 재무 숫자 → LLM이 서술.
- **점수(숫자) = DB / 서술(보고서) = 캐시** — 분리.
- 장투 케어는 lazy(들어와서 봄)+종목별이라 토큰 부담 적음.

## 5. DB / 갱신

| 테이블 | 내용 | 갱신 |
|---|---|---|
| `long_term_score` | 3축 점수 + total + grade | 일 1회 배치 |
| `long_term_score_history` | 일별 스냅샷 | 일 1회 → 히스토리 추세 |

**입력 출처:** `financial_summary`(부채·유동·매출/순익 YoY) · `stock_indicator`(ROE·영업이익률·EPS) · `investment_profile`+`recommendation_cache`(궁합)

> 뉴스/감성(sentiment)은 장투 점수에 **미반영** (화면=관련 기사, 점수=재무/성장/궁합 3축).
