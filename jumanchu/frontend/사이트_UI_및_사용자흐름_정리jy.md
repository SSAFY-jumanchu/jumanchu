# 사이트 UI 및 사용자 흐름 정리

이 문서는 주만추 서비스의 기존 기획 자료를 바탕으로, 실제 사이트 화면 구성과 사용자 흐름을 팀원이 바로 이해할 수 있도록 정리한 초안이다.[file:6][file:7][file:8]

## 1. 서비스 한 줄 정의

주만추는 사용자의 투자 성향과 행동 데이터를 바탕으로 주식과의 **궁합 점수**를 계산하고, 장기적으로 잘 맞는 종목을 추천해주는 서비스다.[file:8]
또한 추천에서 끝나지 않고, 사용자가 Like한 종목을 오래 보유할 수 있도록 월간 재검증, 하락 시 심리 지원, 보유 마일스톤 기능까지 이어지는 구조를 가진다.[file:7][file:8]

## 2. UI 설계 방향

### 핵심 UI 컨셉

- 복잡한 투자 데이터를 숫자 나열로 보여주기보다, "나와 얼마나 잘 맞는 주식인가"를 직관적으로 보여준다.[file:8]
- 초보 투자자도 이해할 수 있도록 설명형 카드, 궁합 점수, 쉬운 문장 중심 UI를 사용한다.[file:8]
- 추천 이후의 행동까지 연결되도록 저장, 재검증, 복기 흐름이 자연스럽게 이어져야 한다.[file:7]

### UI 톤앤매너

- 친근하고 감정적으로 부담 없는 표현 사용: 예) "아직 좋은 파트너예요", "지금 팔기엔 아까운 타이밍이에요".[file:7]
- 금융 서비스이지만 차갑고 딱딱한 화면보다, 관계·궁합 메타포를 살린 부드러운 인터랙션 중심으로 설계한다.[file:7][file:8]
- 핵심 수치(궁합 점수, ROE, 부채비율, EPS 증가율, PBR 변화)는 카드형으로 요약하고, 자세한 정보는 펼쳐보는 방식으로 구성한다.[file:7][file:8]

## 3. 전체 사이트 구조

### 주요 화면 구성

| 메뉴/화면 | 목적 | 핵심 UI 요소 |
|---------|------|-------------|
| 온보딩 | 투자 성향 수집 | 질문 카드, 진행률 바, 선택형 답변 UI |
| 궁합 분석 중 | 프로필 벡터 생성/로딩 | 로딩 애니메이션, 분석 단계 표시 |
| 추천 스와이프 | 종목 추천 제공 | 종목 카드, 궁합 점수, Like/Pass 버튼 |
| 종목 상세 | 추천 이유 설명 | 지표 카드, 뉴스 요약, 섹터 정보, 추천 근거 |
| 관심 종목 | Like한 종목 관리 | 저장 리스트, 점수 변화, 상태 배지 |
| 장투 케어 | 보유 유지 지원 | 월간 재검증 카드, 하락 알림 카드, 마일스톤 배지 |
| 마이페이지 | 내 성향/행동 확인 | 투자 성향 요약, 선호 섹터, 기록/패턴 요약 |

이 구조는 온보딩 설문 → 유저 프로필 벡터 → Stock DNA → 궁합 점수 계산 → 추천 스와이프라는 기본 시스템 흐름을 화면 단위로 풀어낸 것이다.[file:8]
추천 이후에는 Like 저장 종목을 중심으로 장투 지원 기능이 이어지는 2단계 구조로 본다.[file:7][file:8]

## 4. 화면별 UI 상세

### 4.1 온보딩 화면

목적은 사용자의 투자 성향을 8개 질문으로 수집하고, 궁합 계산에 필요한 프로필 벡터를 만드는 것이다.[file:8]
질문은 한 화면에 하나씩 보여주거나 2~3개씩 묶되, 사용자가 어렵지 않게 답할 수 있도록 선택형 카드 UI로 구성한다.[file:8]

#### 포함 요소

- 상단: 서비스 소개 문구, 진행률 바
- 본문: 질문 카드
- 답변 방식: 단일 선택 버튼, 슬라이더, 멀티 선택 칩(관심 산업)
- 하단: 이전 / 다음 버튼

#### 주요 질문 항목

- 투자 목적
- 투자 기간
- 투자 경험
- 리스크 이해도
- 손실 대응 방식
- 투자 스타일
- 투자 방식(장기/단기)
- 관심 산업[ file:8]

### 4.2 궁합 분석 중 화면

온보딩이 끝나면 사용자의 응답을 바탕으로 프로필 벡터를 만들고, 종목 데이터와 매칭해 궁합 점수를 계산한다.[file:8]
이 구간은 단순 로딩이 아니라 "당신과 맞는 주식을 찾는 중" 같은 메시지로 기대감을 주는 화면이 적합하다.[file:8]

#### 포함 요소

- 로딩 애니메이션
- 분석 단계 표시: 성향 분석 → 종목 성격 매칭 → 궁합 계산
- 짧은 설명 문구

### 4.3 추천 스와이프 화면

서비스의 메인 경험은 궁합 점수를 기반으로 종목을 추천하는 스와이프 UI다.[file:8]
사용자는 추천 종목을 빠르게 넘겨보며 Like 또는 Pass를 선택하고, Like는 사실상 매수 혹은 장기 관심 진입으로 간주된다.[file:7][file:8]

#### 추천 카드 구성

- 종목명 / 티커
- 궁합 점수 (0~100)
- 한 줄 요약: 예) "안정형 투자자에게 잘 맞는 반도체 대장주"
- 핵심 이유 3개
- 섹터 정보
- 간단 지표 요약: 변동성, 가치, 성장, 안정성[ file:8]

#### 하단 액션

- Pass
- Like
- 상세 보기

### 4.4 종목 상세 화면

종목 상세 화면은 "왜 이 주식이 추천되었는지"를 설명해 신뢰를 높이는 역할을 한다.[file:8]
핵심은 점수만 보여주는 것이 아니라, 리스크 궁합·기간 궁합·경험 궁합·테마 궁합·스타일 궁합을 분해해서 설명하는 것이다.[file:8]

#### 상세 섹션 예시

- 궁합 총점
- 궁합 요소별 점수
- 종목 성격(Stock DNA)
- 뉴스 요약
- 관련 섹터/업종 정보
- 추천 이유 설명 카드
- Like 저장 버튼[ file:6][file:8]

## 5. 추천 이후 사용자 흐름

이 서비스는 추천만 하고 끝나는 구조가 아니라, Like 이후 사용자를 계속 붙잡는 장투 지원 흐름이 핵심이다.[file:7]
따라서 추천 완료 후부터는 "보유 유지 지원" 중심의 화면 설계가 필요하다.[file:7]

### 5.1 관심 종목 저장 화면

Like한 종목을 모아 보는 리스트 화면이다.[file:7]
사용자는 저장한 종목의 현재 상태, 궁합 점수 변화, 최근 재검증 결과를 한 번에 확인할 수 있어야 한다.[file:7]

#### 카드 구성

- 종목명
- 현재 상태 배지: 유지 / 주의 / 재고
- 현재 궁합 점수
- 최근 재검증 날짜
- 하락 알림 여부
- 상세 진입 버튼[ file:7]

### 5.2 월 1회 장투 재검증 화면

Like 이후에는 매달 자동으로 장투 적합성을 다시 점검하는 화면 또는 카드가 제공된다.[file:7]
평가 기준은 ROE, 부채비율, EPS 증가율, PBR 변화의 4개 축이다.[file:7]

#### 재검증 UI 구성

| 지표 | 기준 | 의미 |
|------|------|------|
| ROE | 10% 이상 | 수익성 유지 여부 |
| 부채비율 | 200% 이하 | 재무 안정성 |
| EPS 증가율 | 전년 대비 플러스 | 성장 지속 여부 |
| PBR | 최초 Like 시점 대비 ±30% 이내 | 저평가 매력 유지 여부 |

결과는 초보자도 바로 이해할 수 있게 3단계 신호로 보여준다.[file:7]

- 🟢 유지: 아직 좋은 파트너예요.[file:7]
- 🟡 주의: 지표 하나가 꺾였어요, 조금 지켜봐요.[file:7]
- 🔴 재고: 처음 추천 이유가 흔들리고 있어요.[file:7]

### 5.3 하락 시 심리 지원 화면

주가가 하락했을 때 사용자가 불안해서 바로 매도하지 않도록 심리 지원 카드가 자동 노출된다.[file:7]
이 화면은 숫자보다 "지금 왜 버텨도 되는지"를 설명하는 메시지형 UI가 중요하다.[file:7]

#### 트리거별 노출 예시

- 주가 -5% 이하: 단기 하락, 펀더멘털은 이상 없어요.[file:7]
- 주가 -15% 이하: 긴급 재검증 카드 노출.[file:7]
- 보유 30일 경과: 한 달 버텼어요, 장투 점수 유지 중.[file:7]
- 보유 90일 경과: 3개월 버텼어요, 궁합 점수 재계산 결과 제공.[file:7]

### 5.4 보유 마일스톤 화면

30일, 90일, 180일, 1년 등 특정 보유 시점에 배지와 스냅샷을 제공해 장투를 게임처럼 느끼게 하는 넛지 기능이다.[file:7]
사용자가 "버틴 기록"을 시각적으로 축적하게 만들어 매도 충동을 줄이는 역할을 한다.[file:7]

#### UI 요소

- 보유 기간 배지
- 해당 시점 지표 스냅샷
- 당시 궁합 점수 기록
- 축하 메시지 / 다음 마일스톤 안내[ file:7]

## 6. 전체 사용자 흐름도

### 기본 흐름

```text
랜딩 진입
→ 서비스 소개 확인
→ 시작하기
→ 온보딩 설문 8문항 응답
→ 사용자 프로필 벡터 생성
→ 궁합 분석 로딩
→ 추천 스와이프 진입
→ 종목 Like 또는 Pass
→ 상세 확인
→ 관심 종목 저장
→ 장투 케어 진입
→ 월간 재검증 / 하락 알림 / 마일스톤 확인
→ 마이페이지에서 내 성향 및 기록 확인
```

이 흐름은 설문 기반 추천에서 출발해, 실제 행동과 보유 흐름을 반영하는 장기 사용자 경험으로 확장되는 구조다.[file:7][file:8]

### 추천 상세 흐름

```text
추천 카드 노출
→ 궁합 점수 확인
→ 추천 이유 확인
→ 상세 보기 진입
→ 궁합 요소별 설명 확인
→ Like 저장
→ 관심 종목 목록 반영
```

### 장투 유지 흐름

```text
Like 저장
→ 월간 자동 재검증
→ 유지/주의/재고 상태 부여
→ 주가 하락 이벤트 감지
→ 심리 지원 카드 노출
→ 보유 기간 마일스톤 도달
→ 배지/스냅샷 제공
→ 장기 보유 의사결정 지원
```

## 7. 메뉴 구조 제안

### 하단 탭 기준

- 홈: 오늘의 추천, 빠른 진입
- 추천: 스와이프 추천 메인
- 관심종목: Like한 종목 리스트
- 장투케어: 재검증/하락 카드/마일스톤
- 마이: 내 성향, 기록, 설정

초기 버전에서는 기능 과다를 피하기 위해 하단 탭 5개 이내로 제한하는 것이 적절하다.[file:7][file:8]
핵심 경험은 추천과 관심종목, 장투케어 3축으로 유지하는 것이 좋다.[file:7][file:8]

## 8. MVP 기준 우선 구현 화면

### Must Have

- 랜딩 / 시작 화면
- 온보딩 설문 화면
- 궁합 분석 로딩 화면
- 추천 스와이프 화면
- 종목 상세 화면
- 관심 종목 저장 화면[ file:8]

### Should Have

- 월간 재검증 카드 화면
- 하락 시 심리 지원 카드
- 마이페이지 성향 요약 화면[ file:7]

### Could Have

- 보유 마일스톤 배지 히스토리
- 행동 기반 성향 재학습 화면
- 업종 평균 비교 시각화[ file:7][file:8]

## 9. 팀 공유용 한 줄 정리

주만추 사이트는 "온보딩으로 성향을 파악하고, 궁합 점수 기반으로 종목을 추천한 뒤, Like한 종목을 오래 보유할 수 있도록 계속 케어하는 구조"로 설계하면 된다.[file:7][file:8]
