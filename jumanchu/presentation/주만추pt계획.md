# 주만추 12분 발표용 슬라이드 구성안 (v2 — 프로젝트 맥락 반영)

> v2 변경 요약: 16→14장 압축 · **궁합추천 + Stock DNA를 클라이맥스 2장으로 격상** · Vue/API/ERD 3장을 "시스템 구조" 1장으로 통합 · 인기랭킹·호가창·커뮤니티·뉴스는 "추가 구현"으로 압축.
> 발표 주체: 미정(누가 발표해도 되는 범용 구조). 발표 시간: 12분.

짧은 기술 발표는 문제 정의 → 해결 방향 → 구현 구조 → 데모 순으로 전개하고, 한 슬라이드에 핵심 메시지 하나만 담는 구성이 효과적이다.

## 이 발표의 척추 (반복해서 각인시킬 한 줄)

**온보딩(성향 수집) → 궁합추천(나랑 맞는 종목) → 장투케어(추천 이후 관리)** — 하나로 이어지는 사용자 흐름.
그 추천의 엔진이 **Stock DNA**(종목 4축 성격 점수)다.

## 발표에서 가장 강하게 보여줄 것 (강조 포인트)

1. **단순 종목 추천 앱이 아니다** — 초보 투자자의 장기 투자 습관 형성을 돕는 서비스.
2. **궁합 추천 = 차별점** — 사용자 성향과 종목 DNA를 매칭해 "나랑 잘 맞는 종목"을 제시.
3. **Stock DNA 알고리즘** — 4축(변동성·저평가·성장성·안정성) × 시장별 분위수 정규화 × 2,649종목 적재. (Algo 하이라이트)
4. **전부 실데이터** — KIS 실서버 연동(국내+해외 현재가·일봉·10호가). 목업 아님.
5. **기획→FE→BE→DB→배포 끝까지 구현**한 실행력.

## 간소화 방침 (12분 안에 들어가기 위해)

- 16→14장. 장당 평균 약 50초.
- Vue 구조 + API 설계 + ERD를 각각 한 장씩 기술 덤프하지 않고 **"시스템 구조" 1장**으로 통합.
- 기능 슬라이드(온보딩/궁합/장투케어)는 핵심만, 실제 화면은 **데모에 몰아주기**(중복 제거).
- 인기 종목 랭킹·호가창·커뮤니티·뉴스는 곁가지 → **"추가 구현" 한 줄 + 데모에서 스침**. (많이 만들었다 인상보다 핵심 흐름 강조)

## 슬라이드별 디테일

### 1. 서비스 소개
- 보여줄 것: 서비스명, 로고, 한 줄 소개, 정체성 한 문장.
- 추천 문구: "주만추는 초보 투자자가 자신의 성향에 맞는 종목과 자연스럽게 만나, 건강한 장기 투자 습관을 들이도록 돕는 서비스입니다."
- 포인트: 첫 장은 기능 나열보다 **서비스 정체성**을 먼저 각인.

### 2. 팀 / 역할
- 3인: 강재민(BE — Django 전부·외부 API·CI/CD), 정율(Algo — 추천 도메인 기획 + 알고리즘), 송호영(FE — Vue 전부).
- 강조: 기획부터 풀스택, 배포까지 직접 수행한 범위.

### 3. 문제 정의
- 초보 투자자 페인포인트 3개:
  - 정보는 많지만 무엇을 믿어야 할지 모른다.
  - 본인 기준 없이 즉흥 매매를 한다.
  - 매수 이후 장기 관리 루틴이 없다.
- 포인트: 기술 발표도 문제 정의가 분명해야 설득력이 생긴다.

### 4. 기획 의도 + MVP 범위 (기존 5+6 통합)
- 기획 의도: "단순 추천 앱이 아니라, 성향을 반영해 추천하고 이후 장기 관리까지 잇는 흐름."
- MVP: 온보딩 개인화 / 궁합추천 / 장투케어 / 생성형 AI 설명 보조. (구현/미구현 경계 명확히)

### 5. 사용자 흐름 한 장
- 플로우 다이어그램: Login → Onboarding → 궁합추천(Stocks) → Stock Detail → Watchlist/Holdings → Portfolio/Diary.
- 포인트: 페이지 나열이 아니라 **행동 여정** 설계 결과로 설명.

### 6. 핵심기능 1 — 온보딩
- 온보딩 질문 항목 → 입력 데이터 → 개인화 시작.
- 포인트: 가입 절차가 아니라 **추천 품질을 위한 입력 설계**.

### 7. 핵심기능 2 — 궁합추천 ★
- 궁합 랭킹 리스트, 종목 상세, **추천 사유**.
- 연결 화면: `StocksView`, `StockDetailView`.
- 포인트: 결과만이 아니라 "왜 나랑 맞는지"를 같이 보여줘 신뢰도 확보. (DNA로 자연스럽게 연결)

### 8. 핵심기능 3 — 장투케어
- 관심종목·보유종목·포트폴리오·매매일지(매도사유)·장투 일지연동.
- 연결 화면: `WatchlistView`, `HoldingsView`, `PortfolioView`, `TradingDiaryView`.
- 포인트: 주만추의 차별점은 **추천 후 행동까지 관리**하는 흐름.

### 9. Stock DNA 알고리즘 ★ (기존 13 격상·구체화)
- **종목마다 4축 "성격 점수"(DNA)** 산정 — 궁합 추천의 입력값.
- 4축: 변동성(beta) / 저평가(1/PBR) / 성장성(순이익 YoY) / 안정성(부채↓·유동↑).
- **시장별 분위수 정규화**(한국/미국 따로) → 순위 기반이라 outlier에 면역.
- 산출 현황: 대상 2,956 → 적재 **2,649** (엣지 제외 307). 일 1회 배치로 캐시.
- 궁합 = 온보딩 성향 ↔ 종목 DNA 매칭.
- 포인트: 완벽한 AI 예측 모델이 아니라, **사용자 기준 형성을 돕는 투명한 추천 구조**.

### 10. 생성형 AI 활용
- 역할: 추천 사유 설명 생성, 이해를 돕는 요약 문장.
- 포인트: AI가 추천을 대체한 게 아니라 **결과를 이해하기 쉽게 만드는 UX 보조**.

### 11. 시스템 구조 (기존 11+12 통합)
- Vue: 주요 View / 라우팅(MVP 화면 위주). DRF API: 프론트 요청→백엔드→DB 저장 흐름.
- 핵심 엔티티: User, OnboardingProfile, Stock, StockDNA, Recommendation, Watchlist, Holding, TradingDiary.
- KIS 실서버 연동(국내+해외 현재가·일봉·10호가).
- 포인트: 테이블 이름보다 **"어떤 사용자 행동이 어떤 데이터로 저장되는가"**.

### 12. 구현 결과 / 배포 / 데모 예고
- 구현 완료: 온보딩·궁합추천·장투케어 핵심 흐름.
- 추가 구현(한 줄): 인기 종목 랭킹, 호가창(10호가), 커뮤니티, 뉴스.
- 배포: 실제 접속 가능. 트러블슈팅 1개(인증/API/환경변수/DB 중).
- 데모 예고 멘트.

### 13. 라이브 데모
- 동선: 온보딩 입력 → 궁합 추천 확인 → 종목 상세 → 관심/보유 등록 → 포트폴리오/일지.
- 포인트: 전 기능 보여주지 말고 **MVP 핵심 흐름만 빠르게**.

### 14. 회고 / 확장
- 기획~풀스택~배포 전 과정 경험. 추천보다 더 중요했던 건 **장기 투자 루틴 설계** 경험.
- 확장: 추천 정확도 검증, 실사용자 데이터 기반 개선.

## 추천 발표 톤

기술을 많이 했다는 인상보다, **문제를 정의하고 그것을 사용자 경험과 시스템 구조로 끝까지 구현했다**는 인상을 주는 것이 더 중요하다. 세부 구현보다 문제-해결 구조, 설계 이유, 실행력, 데모 완성도가 더 강하게 기억된다.
